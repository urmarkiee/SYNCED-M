# Firebase project setup

This clone is connected to Firebase project `synedn`.

- Android application: `com.example.syncedn`
- Firebase Android App ID: `1:811884997432:android:85c910e2591bca405cafcd`
- Firestore: Standard edition, `(default)` database, Singapore (`asia-southeast1`), with deletion protection enabled

The app's existing Firebase Authentication and Firestore SDK dependencies are retained. Password recovery now uses Firebase Authentication's email reset link. The client no longer writes passwords to Firestore or contains the old Brevo API key. The new Firestore database is empty; no account or team data was migrated.

## Required Firebase Console setup

1. Email/Password sign-in is enabled in Firebase Authentication for this project.
2. Google sign-in is enabled for `synedn`. The Android debug SHA-1 and SHA-256 fingerprints are registered. `app/google-services.json` has been refreshed and includes the Android OAuth client and generated web OAuth client ID. The app reads `default_web_client_id` generated by the Google Services Gradle plugin; it does not need a hard-coded client ID. Register the release certificate fingerprints before distributing a release-signed build.
3. The prior source contained a Brevo API key. Revoke that key in Brevo and create a replacement if another service still needs it. Do not put the replacement in Android code.
4. Review Firestore rules before inviting members. Team users can read roster profiles in their own team, including profile fields the app currently stores together. The six-character team invite code acts as the join credential; keep it private and rotate it if shared outside the team.

The rules in this clone require signed-in users, validate document shape, use the team document's `leaderUid` for leader authority, and deny client access to password reset records. They are a prototype; verify app workflows against them before inviting a wider audience. The app's data model currently keeps contact details and roster fields in the same user document, so team members with roster access can see those contact fields.

## Local run

Open `Synced-N-main` in Android Studio. The Google Services file and `.firebaserc` now target `synedn`. Build and run the `app` debug configuration after completing the Authentication provider setup above.


## Backend change status

The app uses Firebase Authentication and Cloud Firestore as its backend; no separate API server is required for the current features. The current source includes tightened Firestore profile rules and UID-based profile operations. See `docs/FIRESTORE_RULES_REVIEW.md` for the rule review and remaining deployment/build verification steps. The updated local rules must be deployed to project `synedn` before release.
